# HANFLIX 큐시트 체크 (2026 학부합창대회)

각 학부가 **자기 구글 드라이브에 만든 큐시트 시트 링크**를 넣으면 **항목별 피드백**을 주고, 학부가 **반영할 피드백을 고르면** 고른 것만 반영된 큐시트를 **원본과 별도의 새 구글 시트**(2026 2차 큐시트 양식 그대로)로 만들어 주는 웹사이트입니다. 첨부한 원본 시트는 읽기만 하고 바꾸지 않으며, 특정 시트(예: TFT 전체 큐시트)에 묶여 있지 않습니다. 상단 메뉴의 **AI 작성**에서는 원하는 큐시트를 요구사항(프롬프트)과 기획안 · 가사 · 콘티 파일로 설명하면 OpenAI가 큐시트를 새로 쓰거나 고칠 칸을 제안하고, 그 결과도 같은 방식으로 반영 / 반영 안 함을 골라 받습니다. 디자인은 대회 로고(HANFLIX, #0060D1 파랑 · 검정→남색)를 따릅니다.

## 진행 순서

1. **첨부** — 학부 큐시트 시트의 공유 설정을 '링크가 있는 모든 사용자 · 뷰어'로 바꾸고 링크를 넣습니다. 탭이 여러 개면 큐시트가 있는 탭을 고릅니다. 원본 시트는 읽기만 합니다.
2. **반영할 피드백 고르기** — 결과 화면에 총평과 항목별 피드백이 나옵니다. 피드백마다 **원래 → 수정 후**를 보고 **반영 / 반영 안 함**을 고릅니다.
   - **자동 정리**(Run Time·조명 표기, 빈칸 X/유지, 셀 병합 등 형식): 처음부터 반영으로 골라져 있고 끌 수 있음
   - **반영하면 이렇게**(그 칸에 들어갈 문구가 정해진 수정): 시트 값만으로 계산한 확실한 것은 반영, 예시(`[ ]`, 화면에서는 파란 글씨)가 들어가는 것은 처음에 반영 안 함 — 골라서 반영. '수정 후 문구 고치기'로 고친 문구로 반영 가능
   - **직접 고치기**(11분 맞추기, FX 효과 고르기 등 학부가 정할 것): 반영할 수 없음 → 받은 시트에서 고침
   - 한꺼번에: 수정요망 모두 반영 · 모두 반영 · 모두 반영 안 함 · 처음 선택으로, 항목별 '이 항목 모두 반영'. 같은 칸을 바꾸는 항목을 함께 고르면 알려 주고 아래쪽 문구가 들어감
   - '이 무대에 맞춘 제안' 중 칸에 넣을 수 있는 것(간주 구간 마이크 OFF/ON 시각, 절정 볼륨, 절정 밝기)도 골라서 반영
   - 미리보기(`#/sheet`)로 반영한 모습을 2026 양식 표로 확인
3. **피드백 반영한 구글 시트 받기** — '피드백 반영한 구글 시트 만들기'를 누르고 구글 계정으로 로그인('허용')하면, 고른 피드백만 반영된 큐시트를 2026 2차 양식 엑셀로 만든 뒤 **구글 시트로 변환해 학부 계정의 드라이브에 새 파일**로 올리고 바로 엽니다(열 너비·셀 색·글꼴·테두리·병합 유지). 권한은 `drive.file`(이 사이트가 만든 파일에만 접근)뿐이고 첨부한 원본은 바뀌지 않습니다. 예시가 들어간 칸과 '(작성 필요)' 칸은 붉게 표시되고, 원하면 반영으로 바뀐 칸을 노란색으로 표시합니다.

### 구글 로그인 설정 (처음 한 번)

새 구글 시트를 바로 만들려면 Google OAuth 클라이언트 ID가 필요합니다. 없으면 대신 반영본 엑셀을 내려받아 새 시트에서 '파일 → 가져오기'로 넣도록 안내합니다.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만들고 **Google Drive API**를 사용 설정합니다.
2. **OAuth 동의 화면**: 사용자 유형(학부 디렉터가 학교 계정만 쓰면 '내부', 개인 계정도 쓰면 '외부' 후 게시), 앱 이름 'HANFLIX 큐시트 체크', 범위 `.../auth/drive.file`.
3. **사용자 인증 정보 → OAuth 클라이언트 ID → 웹 애플리케이션**, 승인된 JavaScript 원본에 `https://cuesheet-feedback-2026.netlify.app`.
4. 만든 클라이언트 ID(비밀값 아님)를 Netlify 환경 변수 `GOOGLE_CLIENT_ID`(범위: Functions)에 넣고 다시 배포합니다. 사이트는 `/api/config`로 이 값을 읽습니다.

- 배포 주소: https://cuesheet-feedback-2026.netlify.app
- Netlify 프로젝트: `cuesheet-feedback-2026` (운영 주소 공개, 미리보기 배포는 Netlify 팀 로그인 필요)

결과 화면 항목마다 기준 줄 끝의 '가이드'는 그 칸의 작성법으로, '이 무대에 맞춘 제안'의 '구성법'은 무대 연출 계획으로 이어집니다. 첨부한 큐시트와 고른 반영 여부·고친 문구는 브라우저 탭(sessionStorage)에만 남습니다.

상단 메뉴는 홈 · AI 작성 · 가이드입니다. 피드백 결과는 따로 있는 메뉴가 아니라 큐시트를 첨부했을 때 이어지는 단계로만 나오고, 다른 큐시트를 점검하려면 결과 맨 위 '다른 큐시트 첨부'(또는 홈)를 누릅니다. 예전 주소(`#/check`, `#/check/{항목}`, `#/report`, `#/download`)는 `#/result`로 넘어가며, 항목을 가리키던 주소면 그 항목을 펼쳐서 보여 줍니다. 예전 'AI 대안' 주소(`#/ai`)는 `#/write`로 넘어갑니다.

불러온 큐시트는 브라우저 탭(sessionStorage)에만 남고, 새로고침해도 이어서 볼 수 있습니다.

## 고칠 것: 같은 말은 한 번만

결과 화면은 피드백을 **고칠 방법(종류)마다 한 묶음**으로 보여 줍니다(`engine/digest.js`). 묶음 제목이 고칠 방법이고, 설명과 근거는 묶음에 한 번만, 아래 줄마다 위치 · 원래 → 수정 후 · 반영 여부만 있습니다. 예시 학부 기준으로 모두 펼쳤을 때 되풀이되는 줄이 36%(451줄 중 162줄)에서 4%(212줄 중 8줄)로, 화면 길이가 18,245px에서 7,760px로 줄었습니다.

- **같은 칸은 한 줄**(`remedy.mergeSameCell`): 한 칸에 여러 피드백이 걸리면(예: 조명 Details 한 칸에 'FX로 지정하지 않음' 3개 + '스트로브를 오래') 차례대로 적용한 최종 문구 하나로 합치고, 나머지는 '함께 해결'로 적습니다. 반영 여부는 하나로 고르고(합쳐진 피드백은 `dupOf` · `choiceId`로 따라감), 같은 칸끼리 부딪치는 일이 없습니다.
- **같은 자동 정리는 한 번**: 켜고 끄는 단위(fixId)가 같으면 한 줄에 바뀐 칸 목록을 함께 보여 줍니다.
- **되풀이 안내는 한 번**: 파란 글씨(예시) 안내는 고칠 것 머리에 한 줄, 문구 고치기는 줄마다 ✎ 버튼, 앞 무대와 똑같은 음향 · 조명 제안은 '합창 마이크 4개 정도 (무대 1과 같음)'처럼 짧게.

| 표시 | 뜻 |
|---|---|
| 반영 / 반영 안 함 | 반영하면 그 칸에 수정 후 문구가 들어감. 형식만 맞춘 자동 정리는 처음부터 반영 |
| <mark>파란 글씨</mark> | 학부만 알 수 있는 부분이라 예로 넣은 것(엑셀 · 메시지 · 받은 시트에서는 `[ ]`, 붉은 칸) |
| 고친 문구 | ✎로 학부가 고친 문구 — 이 문구로 반영 |
| 직접 고치기 | 칸 하나로 반영할 수 없는 것(예: 무대 시간 11분 40초 → 11분 이내) — 받은 시트에서 고침 |

피드백 메시지도 같은 묶음 순서로 씁니다(`1. 고칠 방법 (항목 · n곳)` 아래 `- [반영] 위치: 원래 → 수정 후`, 자동 정리는 한 줄). 검토용 엑셀의 '피드백 목록'에는 피드백마다 원래 · 수정 후 · 반영 열이 그대로 들어갑니다(합쳐진 피드백은 대표 피드백의 반영 여부를 따름).

| TFT 조명 Details 기준 | **학부가 주인공을 쓰는 무대만**: 조명 Details에 주인공의 동선(어디에서 어디로) · 의상 · 위치(어느 Pin 자리)를 구체적으로 — 빠진 것을 수정요망으로 알려 주고, 세부 내용에 적힌 동선으로 수정 후 예시를 만듦. 솔로만 있는 무대에는 적용하지 않음 |
| 무대 내용 · 개사 분석 | 노래하는 구간인데 마이크가 없음, 노래하는 주인공·솔로에게 무선(핸드) 마이크가 없음 → 수정요망 |

### TFT 조명 Q&A

학부 질문에 TFT가 답한 내용을 점검 기준으로 넣었습니다(`rules-light.js`의 `qaRules` · `fxRules`, 단어 목록은 `vocab.js`). 작성 가이드 '조명'과 AI 작성 지시문에도 같은 내용이 들어 있습니다.

| 질문 | 사이트가 하는 일 | 수준 |
|---|---|---|
| 콰이어만 / 무대 아래 단원 / 십자가만 비추기, 샤워처럼 쏟아지는 빛 | FX가 있어야 하는 연출로 보고, FX1·FX2로 지정하지 않으면 알려 줌(FX 2종류에 포함). 무대 아래 단원은 서는 위치가 없으면 알려 줌 | 수정요망 |
| 가사·비트에 맞춘 연속 점멸, 순간적인 반짝임, 두근두근 점멸 | FX로 세지 않음(스트로브 단어에서 '번쩍이'를 뺌). 어떤 조명을 · 어떻게(간격 · 횟수 · 밝기 변화)가 빠지면 알려 줌. '깜빡임 X'처럼 하지 말라는 뜻은 제외, 줄이 나뉜 문장은 앞뒤 줄까지 봄 | 수정요망 |
| 단순 점멸에 FX 이름을 붙임('FX2 점멸') | 'FX가 아님'으로 알려 주고 '어떤 효과인지 없음'은 내지 않음 | 참고 |
| 같은 FX를 여러 번 | 종류로만 셈(같은 효과 반복은 1종류), 3종류부터 수정요망 | 수정요망 |
| FX에 쓰이는 핀 | FX를 쓰는 행에 켜 둔 핀이 있으면 겹치지 않는지 확인하라고 알려 줌(칸의 마지막 큐로 켜짐/꺼짐 판단) | 참고 |
| 앞줄 강조 | '앞줄 강조'인데 무대 조명이 상단보다 어두우면(또는 무대를 끄고 상단을 켜면) 무대를 밝게 · 상단을 어둡게 | 수정요망 |
| 연한 색과 밝기 | 연한 색에 밝기를 40% 이하로 적으면 밝기를 낮출 필요는 없다고 알려 줌. '하늘색 / 연하게'를 추정 %로 바꿀 때도 같은 말을 덧붙임 | 참고 |
| 레퍼런스 사진 | 조명 칸 · Details(비고는 조명 · 색 이야기일 때)에 레퍼런스가 있으면 채플 환경이 달라 똑같지 않을 수 있다고 한 번 알려 줌 | 참고 |
| 밝기 정밀도 | 소수점 첫째 자리까지 읽고 정리(`37.5` → `37.5%`, 핀 `37.5%` → `ON (37.5%)`), 둘째 자리부터는 반올림 값을 알려 줌 | 참고 |
| 고보 | TFT가 주는 패턴 사진에서 고르고, 무대 전체에 고르게 비출 수 있는지는 설치 후 확인 | 참고 |
| 무대 100%에서 핀, 구역 3등분 | 가이드와 AI 지시문에 설명(점검 항목은 없음) | — |

결과 화면의 'FX 지정'에도 콰이어만 비추기 · 샤워처럼 쏟아지는 빛 · 무대 아래 단원 비추기 · 십자가만 비추기를 넣었습니다. 실제 학부 큐시트 12개로 확인했을 때 이 규칙이 새로 낸 수정요망은 없고, 참고만 몇 개(FX 구간의 핀, 고보, 레퍼런스) 늘었습니다.

### 음향 · 조명 제안 (무대 내용 · 개사 분석)

무대마다 출연 구성(콰이어·댄서·주인공·솔로), 개사의 분위기(차분·희망·따뜻·열정·경건), 곡 흐름(간주·첫 소절·반복되는 가사로 찾은 절정·끝), 대사·악기를 읽어 제안을 만듭니다. 제안은 수정요망 개수에 넣지 않고, 결과 화면의 '음향 · FD'와 '조명' 항목(칩에 '제안' 표시)과 총평, 피드백 메시지, 검토용 엑셀 총평 시트에 들어갑니다.

- 음향: 합창 마이크 개수(콰이어 6명당 1개 정도, 최종 수량은 TFT 음향팀과 확인), 노래하는 주인공·솔로의 무선 마이크(기본 2대), 간주·안무 구간 OFF와 가사 시작 ON, 절정에서 합창 볼륨, 대사·악기(DI·마이킹)
- 조명: 분위기에 맞는 상단 색과 밝기 범위, 분위기가 바뀌는 시점, 도입(간주는 어둡게 서서히 · 밝은 곡은 첫 소절부터 즉시), 절정에서 가장 밝게, 주인공·솔로의 Pin 자리, 안무 구간 무대 전체 70% 이상, 노래 끝 암전
- 지금 큐시트와 비교: 절정의 밝기가 도입보다 높지 않으면 함께 알려 줌

실제 학부 큐시트 내용은 사이트에 넣지 않았습니다. 예시는 모두 가상 학부입니다.

## AI 작성 (OpenAI)

규칙 기반 피드백과 피드백 반영본은 AI 없이 동작합니다. AI 작성은 그 위에 더하는 기능이고, 피드백을 골라 반영하는 흐름은 그대로입니다.

- **새 큐시트 작성** — 요구사항 · 기획안으로 2026 2차 양식 큐시트 전체를 작성 → 미리보기 → '이 큐시트로 피드백 받기'로 점검 · 반영 고르기 · 구글 시트 받기. AI가 모르는 값(인원, 의상, 곡 제목 등)은 지어내지 않고 `[ ]` 자리표시로 남기며, 받은 시트에서 붉은 칸(직접 채울 칸)으로 표시됩니다.
- **첨부한 큐시트 고치기** — 첨부한 큐시트(지금 고른 피드백을 반영한 상태)를 행 id와 함께 보내면 바꿀 칸(`changes`)과 새 행(`inserts`)을 돌려받습니다. 항목마다 원래 → 수정 후 · 반영 / 반영 안 함 · 수정 후 문구 고치기를 하고, 반영한 것만 새 구글 시트 · 엑셀 · 피드백 메시지에 들어갑니다. '수정요망도 함께 고치기'를 켜면 아직 반영하지 않은 수정요망도 함께 보냅니다. 요청은 여러 번 이어서 할 수 있고, 결과는 피드백 결과 화면의 'AI 요청 반영'에서도 고를 수 있습니다.
- **첨부 파일**(8개까지) — 텍스트 · CSV · 마크다운은 그대로, 워드(.docx) · 한글(.hwpx) · 파워포인트(.pptx)는 브라우저에서 글자만 꺼내고, 엑셀은 탭별 표를 글자로 바꿔 보냅니다. PDF · 이미지(콘티 · 동선도)는 그대로 보내 AI가 직접 읽습니다(합계 3.5MB, 큰 이미지는 줄여서). 한글(.hwp)과 예전 오피스 파일은 PDF로 저장해서 올리도록 안내합니다.
- **처리 방식** — `/api/ai/start`가 요청을 확인해 Netlify Blobs(`ai-jobs`)에 잠시 넣고 백그라운드 함수 `/api/ai/run`을 깨웁니다(응답이 1분을 넘을 수 있어서). 백그라운드 함수가 OpenAI Responses API를 구조화된 JSON(스키마 고정)으로 부르고 결과를 Blobs에 넣으면, 사이트가 `/api/ai/status`로 기다렸다가 받은 뒤 지웁니다. 첨부 파일이 든 요청은 실행이 끝나는 대로 지우고, 가져가지 않은 결과는 하루 뒤 정리합니다. 기다리는 중에 다른 화면을 보거나 새로 고쳐도 이어서 기다립니다.
- **켜기** — Netlify AI Gateway를 쓸 수 있는 팀(크레딧 요금제)이면 함수에 `OPENAI_API_KEY` · `OPENAI_BASE_URL`이 자동으로 들어가 따로 설정할 것이 없습니다. 아니면 Netlify 프로젝트 설정 → Environment variables에 `OPENAI_API_KEY`(범위: Functions, 비밀값)를 넣고 다시 배포합니다. 둘 다 없으면 AI 작성 화면에 안내가 나오고 요청 버튼이 잠깁니다.
- **설정(선택)** — `OPENAI_MODEL`(기본은 `modelList()`의 첫 모델, 쓸 수 없으면 다음 모델로), `OPENAI_REASONING`(추론 정도, 기본 `low`).
- **개인정보** — 요구사항 · 첨부 파일 · (고치기는) 큐시트 내용이 OpenAI로 전송됩니다. 화면에 이 안내가 있고, 연락처 같은 개인정보는 넣지 않도록 합니다.
